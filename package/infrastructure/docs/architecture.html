What the stack provisions

Shared (created once)

  • VPC 2 AZs, 1 NAT gateway
  • ECS Fargate cluster with Container Insights v2
  • DNS Route 53 hosted zone lookup for flowmachine.io

Per service (looped)

  • CloudWatch log group (1-week retention)
  • ECR repo reference (existing)
  • ACM cert (DNS-validated)
  • Fargate task definition (256 CPU / 512 MiB)
  • ALB-fronted Fargate service (HTTPS, redirect HTTP)
  • Route 53 alias record → ALB
  • Custom health check on target group
  • CfnOutput: URL + ALB DNS

Code walkthrough

Inputs

InfrastructureStackProps extends cdk.StackProps with imageTag: string — the Docker tag to deploy (likely git SHA from CI).

ServiceSpec describes one service: id, repoName, hostname, containerPort, healthCheckPath.

Constructor (lines 43–64)

  1. Create VPC — 2 AZs, 1 NAT.
  2. Create ECS cluster in that VPC with Container Insights v2.
  3. Look up the existing Route 53 hosted zone.
  4. Loop SERVICES → createService(...) for each.

createService (lines 66–141)

  1. LogGroup — 1-week retention, destroyed with the stack.
  2. ECR repo — imported by name (managed outside).
  3. ACM cert — DNS-validated against the zone.
  4. Task definition — Fargate, 256 CPU / 512 MiB.
  5. Container — image from ECR, port mapping, awslogs driver, NODE_ENV + PORT.
  6. ApplicationLoadBalancedFargateService — public ALB, HTTPS-only, redirectHTTP, private subnets, R53 alias.
  7. Health check — overrides target group path.
  8. Outputs — public URL + ALB DNS.

Traffic path

  1. User hits https://dev.platform.flowmachine.io.
  2. Route 53 resolves to the ALB (alias A-record).
  3. ALB terminates TLS using the ACM cert, redirects HTTP→HTTPS.
  4. ALB forwards to the Fargate task on the configured container port.
  5. Task pulls its image from ECR on cold start; logs stream to CloudWatch.
  6. Outbound traffic from the task → NAT gateway → internet.

Gaps and risks

  • No autoscaling — desiredCount: 1; a single task is a single point of failure.
  • No secrets wiring — only NODE_ENV and PORT; no SSM Parameter Store / Secrets Manager integration yet.
  • Hardcoded "dev." hostnames in what's framed as the production stack — no stage/env split.
  • No WAF, no CloudFront — ALB is directly internet-facing.
  • Shared VPC + cluster for both services — co-located failure domain (acceptable at this scale).
  • Log retention 1 week + RemovalPolicy.DESTROY — fine for dev, probably too aggressive for prod.
